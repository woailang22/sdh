# Player-built room appearance

The approved seamless-world/camp design requires actual four-wall enterable buildings and hiding obstructing roofs/front walls inside. The earned shelter run under8196ec9 proves a paid25-floor/23-wall/one-door room is usable but still looks like a roofless enclosure. Public roofs already exist; placed UUID pieces are intentionally ungrouped. This work completes that concrete rectangular-room presentation without changing construction costs, collision, damage, saved ownership or defenses.

Use existing live floor cells as room seeds. Remove structural wall/door cells from the floor grid (floors beneath walls are allowed), split remaining floors into four-connected components by map/owner, and recognize a component only when its interior rectangle is completely filled and its immediately surrounding rectangle has every wall/door cell with correct side orientation, matching owner/map, and at least one non-corner door. Adjacent rooms with a shared wall remain separate floor components; shared structural members can belong to both visual groups, not duplicate authority entities. Outside floors/unroofed courtyards, incomplete or incorrectly oriented shells, other ownership, empty areas, and nonrectangular components do not acquire a false bounding-box roof. Existing public grouping remains unchanged. L-shaped roofs and arbitrary roof construction are future work, not claimed supported.

Reuse existing tall house wall, roof, front-wall fade and real doorway cue drawing for recognized paid rooms. Use a camp-room caption rather than the generic recipe's door name. A roof is visual only; no free health/collision/shelter/production benefit or new persisted asset. Opening a door keeps the roof structurally present; destroyed wall/door/floor hides it, actual destroyed geometry remains open. Inside/near the boundary, hide roof and fade front walls using the existing0.8-cell rule. Do not repaint stored objects above an opaque outside roof; preserve public-building rendering behavior.

Do not run floor-component discovery every animation frame. Cache only the current buildings array and its length in the engine, retaining live member/floor references so HP/open updates still affect drawing. Authority updates replace the array; local insertion/removal changes length or array. Map resets replace the array. No history map, unlimited ID cache or persisted derived groups. Existing offline floor storage does not contain authority floor entities, so this recognition concerns authoritative paid floor records; offline modes keep their current fallback.

Recognized rooms can contain several boundary doors; draw every actual leaf and retain one primary entrance cue. At a cell containing old destroyed pieces and one paid live replacement, select the live piece; multiple live pieces are not a valid boundary. Retained destroyed-only structure keeps the room footprint but cannot provide a roof. Paid furniture stays in the same depth-sorted list as actors, so the roof covers it outside and actor/furniture front-to-back relationships remain correct inside. Preserve the older public furniture path.
