# 零位移位置同步的服务器减负

本修复承接已批准的移动权威与性能设计。当前 e296463 干净工作区；上轮实际双IAB+六协议样本中，两原生角色2522位置包有2520连续同坐标，另六协议角色2172位置包持续小范围位移。当前每个合法位置包都会扫描建筑并做终点/路径检查，即使玩家并未改变坐标。此前密集营地协议 profile 显示建筑查询占主要移动开销；这不是旧卡顿或射击拒绝的单因证明。

选择在 GameWorld.move 计算 travelled 并验证速度预算后，只对 travelled>0 执行原 buildingsFor、终点碰撞和视线检查。零位移不改变权威位置，仍按原规则更新预算、lastSeen、朝向、射击/冲刺状态、探索记录；非有限坐标、跨空间及越界仍先拒绝。采用严格零比较，不给微小位移豁免。建筑刚关闭到角色当前位置时，零位移包不再被当作一次穿墙尝试拒绝；原拒绝只向客户端纠正到相同坐标，不能移走重叠角色。后续真实位移依然使用最新墙门和建筑状态。

拒绝长期空间缓存：当前建筑字典与对象可以直接插入/替换/移动/删除，未经完整失效边界不能缓存。此前循环换写微测全部更慢，也不采用。选择仅省略无实际路径的重复检查，不改移动速度、路径、建造、攻防、射速、资源、数据库或客户端发送频率。它不解决实际行走中的建筑扫描，也不代表稳定帧率或旧native gate已通过。

先红后绿覆盖：停在刚关闭门的位置能同步朝向/动作但无法继续穿门，开门后正常移动；非法/跨空间零位移拒绝；反复静止不能积累无限移动预算；任意非零位移继续准确碰撞；密集几何读取对照。保存旧 GameWorld 源为 ignored QA baseline（只修相对import路径），隔离比较同样合成状态/输入下的位移结果、零位移语义和实际执行成本。独立只读审查，完整业务测试/类型/构建。真实时钟/SQLite协议负载与原native门槛分开记账，不把微测或RTT改善当物理呈现结论。
