# 客户端移动碰撞范围

目标来自已批准的无缝世界性能要求：减少实际移动中的无关几何工作，不改变墙门、速度、路径或服务端权威。

调查：当前客户端update每次有效移动对完整building列表检查X/Y碰撞；服务器GameWorld.move已做新鲜范围筛选，当前密集夹具移动路径仅25个候选。共享geometry粗筛实验虽在388/5675列表更快，在25小列表五轮均更慢；加小列表分支仍有微测回退，故两种共享navigation候选不采用。它们保持在ignored data作为未交付证据。

选择：只在客户端实际移动分支、列表超过64时，按当前位置、此帧最大行程和既有最大建筑半径筛一次。范围padding为MAX_BUILDING_HALF_EXTENT + PLAYER_COLLISION_RADIUS + abs(speed*dt) + 1e-9。两次轴向检查及自动寻路剩余时间循环复用这一新鲜列表，仍调用原isPositionBlocked。小列表直接用原数组。保留异常门宽的既有保守处理。无跨帧缓存/索引/实体复制，不隐藏实体，不调整渲染、同步、地图/资源密度或服务器代码。

原路径每帧移动总长不大于abs(speed*dt)，所以此范围必须覆盖转角和冲刺，包括当前帧开始在碰撞距离外、但本帧会接近的宽门。数组保留原实体引用；下一帧重建候选，直接新增/删除/移动、开门和损坏仍即时生效。

验证：先用实际Engine更新的远处地板HP读取计数加真实移动距离断言复现多余检查，再覆盖普通/冲刺接近宽门、开门、直接替换/移动实体、已有低帧多拐点及服务器逐包接受测试。保存实际旧Engine源与仅相对导入调整的绑定，在同一内存场景对比完整update而非只测helper；保留所有波动与小列表结果。实际CUA正常游客在独立存档走路复核，只作功能证据，不冒称GPU/FPS或旧多人失败解决。
