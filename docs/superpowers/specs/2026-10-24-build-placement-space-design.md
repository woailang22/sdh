# 建造选择后让出摆放空间

实赚工作台/仓储原生试玩在1280×720发现：人物(0,28)投影(640,360)，完整设施列表覆盖周边可建范围；选择工作台仍不收起。点击拟建(-3,26)的屏幕(608,280)没有发出build，elementFromPoint是底部576×492.67的pointer-events-auto容器空白。源21木6石16废4件保持未扣，服务器无报错。不是材料不足或服务器拒绝。

采用局部方案：BuildingBar选择具体建筑卡片后收为紧凑摆放条，显示当前建筑、共享配方费用、材料不足提示、选择建筑和退出；仍保持原isBuildMode/selectedType，地面点击才调用原build。点“选择建筑”重新展开原分类列表，分类切换不自动收起；退出重进保留上次选取/收起状态，方便连续摆放。保留现深色/青色边框与原图标，不改全局HUD风格。

必要连带修改是App底部外层pointer-events-none、直接子面板pointer-events-auto，空白间距把点击交给地面，真实按钮/面板继续接收输入。不能把整个列表设成点击穿透，否则点击选择卡片会误建；也不通过放大窗口绕过问题。另一方案把完整列表移到侧边，会挡已有任务/聊天且仍限制小窗口，不采用。

范围仅BuildingBar与App底部一行命中规则，不改配方、建造距离/权限/碰撞、资源、地图/图片、模拟或服务端。先用组件实际回调与React元素树验证选择后收起、重选不退出、材料不足禁用/提示、共享费用，旧版先红。原生旧版再留图/命中/未发build证据；修后同一owned存档同一位置同一材料，确认1280×720点击到canvas，正常扣费建工作台/箱、制造和存取及重连，保留已发生的工具误选和输入超时。正常环境/食物结算不回滚。

完整测试/全部QA类型/构建，独立只读源码和最终证据复核后按已有授权推送。此项修复建造可操作性，不声称性能、手机全HUD或全天攻防总目标通过。
