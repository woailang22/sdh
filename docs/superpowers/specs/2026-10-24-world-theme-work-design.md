# 野外地形判定重复计算

承接f547460及已批准的大地图性能设计。全帧工具已交付，但冷地面63.8ms仍存在；上一轮图集候选均未证明收益。这次只调查worldThemeAt内部重复的最近地标、道路和中心半径查询，不重复图集预热，不降低画质或改变地图内容。

旧函数先调用originalWorldThemeAt，再重复查询半径、道路和最近地标。推荐把同一次调用所需信息保存在局部变量并按原优先级返回：出生中心、道路、非营地区域的原主题、营地三个地貌覆盖、原主题回退。originalWorldThemeAt继续保留给旧资源生成，避免改变既有节点。另一方案是新增全地图/逐格缓存，增加内存和失效成本；另一个是减少纹理/细节，会改变画面，均不采用。

成功标准：全部2049×2049整数坐标、道路/水流/地标中线/地貌边缘与浮点特殊值的新旧输出相同；实际generateWorldChunk内容不变；函数不新增状态/缓存。先用独立QA原型和旧函数作oracle；用固定混合坐标交替测全部轮次，再用独立真实Canvas、相同实际素材/相同位置比较整段renderMapGround及RGBA字节。不是只测函数就声称地面卡顿已解决。若真实Canvas没有可复核收益，只保留否定结果，不改生产。

生产候选成立后，先添加地形边界/等价回归与确定性工作预算回归（查询只需一次道路/最近地标遍历，避免平台耗时断言），确认旧版预算失败，再作局部修改。完整测试、类型/构建、原生正常游戏及源码/证据独立只读复核。QA页只在owned loopback，实际Engine由隔离页创建，无游戏状态注入、不接正式数据库；实际游戏仅继续同实赚角色存档。浏览器仅原生CUA，不绕过输入限制。原地形、资源ID/库存/重生、天气、碰撞、分辨率与绘制顺序不变。

这只是完整性能目标中的候选：GPU/总内存/物理呈现、合法路线持续60秒和全境玩法经济仍需各自证据。是否使用生产候选由实际结果决定；单次快值或只有强制读回变快均不足。素材足够，无需生成新图。
