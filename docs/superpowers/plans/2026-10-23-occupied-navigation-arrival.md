# Stop at the reachable end of click navigation

**Problem:** `findPath` already returns a reachable nearby endpoint when a clicked facility occupies its center, but `navigateTo` retains the original blocked coordinate. After consuming the path the engine keeps steering into the obstacle, leaving `targetMovePoint` set; the search update treats this as movement and interrupts gathering. This is distinct from the unresolved GPU/frame stalls.

**Design:** Keep existing bounded A*, collision, input rates, map layouts/IDs, authority and walking speed. Adopt the actual final path point as the movement destination; failed paths cancel as before. Cap automatic movement at each path point, carrying the unused frame time into the next point only after actually reaching it. The initial cap-only experiment reduced walking/dash distance at100ms steps and was replaced; keyboard/joystick still use the original single movement step. Keep arrival cancellation on the following update so actual movement still interrupts searching. Do not add a global path planner or teleport.

**Alternatives:** A special storage/workbench exception leaves the same issue for other occupied destinations; clearing navigation on any collision would hide blocked/temporarily obstructed routes and alter input behavior. Using the path's already validated endpoint is the direct correction.
