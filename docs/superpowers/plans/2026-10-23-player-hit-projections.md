# Player-hit state projection plan

**Goal:** Make actual nonlethal player hits avoid rebuilding every observer's unchanged camp lists while preserving durable combat, death and correction semantics.

**Evidence:** Diagnostic synthetic5675-building/4000-floor world, real server/SQLite and normal clock. Two protocol connections:72 empty shots P95~8.9ms;72 player hits P95~77.5ms. Eight protocol connections:73 player hits P95~1912ms; six response-paced background shooters each complete only two shots with a late reply~8.6s. Full snapshot585 calls~4549.9ms and encode~4289.6ms dominate. Action includes rollback JSON~590.2+parse~642.3ms and persist~1334.1ms; stages overlap and must not be summed. Target HP/maxHP100000 is explicitly diagnostic, not normal combat balance/native acceptance.

**Design:** Only modern string-player-targeted fire gets an internal actionCombat receipt. Reuse runAction's existing full rollback/checkpoint; snapshotPlayer builds the reply. Nonlethal successful fire changes only the shooter and target, so send their own player projections; public player_sync stays on its original200ms visibility cadence. Legacy victims get their own full snapshot; legacy shooters, monster hits and all other actions keep existing behavior. Death or replay requires full shared synchronization; a replay must repair a previously failed death reply without firing again. Always include the victim even if death moved them out of the attacker's map.

**Necessary linked fix:** Independent design review found same-map death lacks position correction today. Expose the existing respawn generation and track the last sent generation per client. Both full and player-only sends force correction when generation changes, updating the marker only after send returns. This also lets later sync/replay recover a failed death notification. No persistent format or game balance change.

This does not eliminate full transaction clones, world saves or monster/raid broadcasts. Keep native crowded combat, ordinary death/balance and large siege capacity as separate unproven gates.

## Review correction and result

Extra out-of-range target synchronization is allowed only when the connection has not received its current server respawn generation. Review found unconditional target inclusion would let a handled-ID replay (or successful unrelated action) force an unrelated remote camp's full snapshot. A fifth remote connection regression failed before the fix and now remains at zero snapshots for both forged replay and unrelated item use. No persistent target metadata was added. Successful legacy combat also includes a victim with an unsent generation, so same-map far-away and cross-map deaths arrive immediately.

Five unit tests and six real-server cases pass. Same-map/cross-map, legacy sender/victim, failed victim death snapshot with replay, previous private commit under SQLite rejection, and pending-fire cancellation are covered. Explicitly removing life correction fails the same-map assertion; removing legacy victim notification in the no-pending case causes a timeout. Source restored before final verification. Full suite40 files/531 tests, type check and production build pass; client remains index-BRl8LPRa.js. Final independent read-only review found no P1/P2 after the replay edge was fixed.
