# Periodic player checkpoints

**Goal:** Keep the existing five-second movement/disconnect durability while avoiding a full-world rewrite when only active player state needs saving.

**Evidence:** Current dense-native gate still has one occupied-slot refusal after wire JSON reuse. Instrumented full periodic checkpoints take32–38ms; they are one source of synchronous work, not the sole proven cause of refusals. The five-second timer unconditionally serializes every building, even with only friendly camp movement/private fire. Reuse the existing transactional private player-commit journal instead of changing fire rate/queue/input.

**Design:** Add persistPeriodic(). If shared NPC state has changed outside a full checkpoint, keep full persist. Otherwise atomically save player+handled rows only for currently active bodies/connections and failed-disconnect retry IDs, using existing saveWorldPlayerCommits. No active/retry/shared work means no write; active rows are saved even if their contents happen to be unchanged. disconnect registers a retry before its existing immediate full save; success clears retries, failure retains them even after body expiry. Successful full checkpoints alone clear the shared flag; a successful periodic batch clears its included retry IDs. Failed transactions leave pending facts intact.

NPC creation also occurs in snapshot()->ensureMonsters, not only ticks. Mark new shared NPCs dirty at creation. Successful simulated NPC ticks without full saves also mark dirty conservatively (cooldowns/targets/animation included). Rollbacks may leave a conservative true flag, which costs an extra full checkpoint but cannot clear earlier unsaved state. Existing shared action/tick atomic saves, NPC/defense semantics, explicit persist(), migration/connect/disconnect/shutdown, schema and recovery overlay remain unchanged.

**Alternatives:** Serializing asynchronously risks older checkpoints overwriting newer committed player state. Saving every account still scales with offline population. Reuse the current active/retry sets and synchronous SQLite batch; do not weaken durability or promise that removing one pause alone will pass the native gate.
