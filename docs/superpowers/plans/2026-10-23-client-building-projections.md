# Skip redundant client building application

> **For agentic workers:** Execute this plan task by task using executing-plans. Keep the approved complete-world/camp scope and prior failed performance samples.

**Goal:** Private player feedback must not rebuild an unchanged authoritative building/floor projection, while actual building changes, warps, new engines and reconnect baselines still apply immediately.

**Evidence and hypothesis:** StateDecoder deliberately retains omitted list references. App.applyGameState nevertheless calls setAuthoritativeBuildings on every decoded private shot/survival reply. The engine filters current buildings, clears/repopulates every floor, and on world forces refreshWorld(true). Prior native measurements show roughly456 setter calls in60 seconds with no building changes. This is a confirmed redundant operation, not yet proof it caused the occupied fire slot or all frame outliers.

**Design:** Keep Engine's explicit mutable setter semantics unchanged. App tracks its last successful building application as one bounded ref containing engine identity, current map and immutable decoded list reference. Apply only when one changes. Reset the ref on onMapZoneChange (including same-map resets) and engine disposal. Engine creation already applies latest stored snapshot even if networking arrived during splash. Failed setter must not advance the ref. Init's legacy building fallback remains when no gameState exists, but a complete gameState must not be applied then immediately overwritten a second time by duplicate init.buildings. Other live player/ammo/resources/monsters/drops/UI feedback continue as before; do not suppress whole callbacks or change input cadence.

**Alternatives:** Caching inside Engine would silently change its explicit mutable setter API and risks stale same-array edits. Comparing whole lists again repeats work already done by the transport. Reducing incoming replies or client fire cadence hides load and changes behavior. Use the transport's existing immutable references at the App boundary with explicit lifecycle resets.
