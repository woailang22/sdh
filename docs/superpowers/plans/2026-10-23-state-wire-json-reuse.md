**Design:** StateEncoder already serializes every shared list for comparison. Store references to the JSON text for lists actually included on each patch in a WeakMap keyed by that patch. Its serializer reuses those texts and normally stringifies other fields; unknown/private patches fall back to ordinary JSON. Never consult a newer encoder baseline for an older patch. Encoded patches are sent synchronously and must not be mutated in place before serialization; replacing a list reference falls back to its current JSON. This adds no duplicate list JSON or strong patch history. server/transport.ts accepts an optional lazy payload serializer, called only after the original closed/backlog checks. It builds the same envelope and counts the final UTF-8 bytes/header before the unchanged send/terminate decision. Modern stateTo/playerStateTo pass the new serializer; legacy/init/other messages remain unchanged.

**Alternatives:** A larger fire queue or weaker timing grace changes combat admission and was rejected. Projection caches require broader invalidation/permission/rollback rules. Reuse the JSON already computed instead. A local pure-wire prototype on5675 buildings/2042369 bytes gives four rounds originalP95~7.5–8.9ms versus proposed~1.1–1.8ms, with identical parsed payload. This excludes snapshots/encode/IO and does not predict the native gate.
