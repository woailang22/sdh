# 无缝世界与野外营地 Implementation Plan

> **For agentic workers:** 使用 executing-plans 执行集成步骤；独立文件的实现与审查使用 dispatching-parallel-agents。步骤使用复选框记录，发现接口依赖时先完成接口再集成。

**Goal:** 将已批准的无缝公共世界、资源探索、野外建营和全天离线攻防接入现有游戏，保持现有渲染性能改进。

**Architecture:** 公共空间使用 `world` 与连续坐标，区域仅为地理信息。地形与初始实体确定性生成，附近数据块加载；服务器保存变化、稳定身份、营地和实际库存。独立营地复用 `home_<ownerId>` 空间标识，但必须先登记再进入。

**Tech Stack:** 现有 TypeScript、React、Canvas 2D、WebSocket、SQLite、Vitest；不引入渲染框架。

本目录 `.git` 仅按当前工作区使用，本轮不进行分支、提交、部署或清档。已有性能修改保留；变更前基线为 141 项测试通过。设计依据为 `docs/superpowers/specs/2026-10-20-seamless-world-camps-design.md`。

## 资源与建筑密度修复（2026-10-21）

用户反馈：资源点太少、看不到建筑。本轮在原有探索设计范围内修复生成规则和可见性，没有扩大世界边界、改营地规则或重置存档。

已确认原因：旧规则将地标周围 42 格的资源、60 格的程序房屋全部排除，且每个区块仅约七分之一概率尝试生成房屋。出生点 `(0,1)` 周围 32 格只有工作台，96 格内没有普通房屋入口；不是整个世界完全没有建筑。旧房屋画法也只有两面院墙，缺少屋顶与用途标识。

### 修改范围与兼容性

- `src/game/world.ts`：保留原生成层，在空隙增加道路建筑和基础资源。新增内容避开实际房屋边界、设施、旧资源和怪物出生位置；出生点中心留空，两侧保留采集空间。新增资源使用独立 `forage` ID，资源与建筑仍按附近区块加载。

### 黑屏：已确认与未确认

**未复现用户的整页卡死，根因仍不确定。** 只读查看最近存档位置后，沿 `(0,1)` 至约 `(113,-12)` 真实行走，并抽样绘制 256 个分布于全世界的区域、五种天气；排查初次运行没有捕获异常、画布丢失或根节点被卸载。不能据此排除特定浏览器、设备、原始操作序列或更长时间下的故障。

确认并修复的一类黑屏隐患：原动画循环在绘图后才安排下一帧，因此某帧抛错会永久停止绘图。回归测试先复现了该停帧行为，再验证修复：

- 先安排下一帧，捕获绘制/更新异常，重建受影响的绘图缓存并延迟重试；不重置玩家、营地或库存。

- 当前浏览器仅保留最近 5 条错误的时间、消息、堆栈和地图坐标，键为 `sdc-render-diagnostics`；不上传、不记录背包或会话令牌。浏览器进程直接崩溃或主线程完全卡死时，这些页面内处理器不保证能执行。

故障注入验证明确区分于真实问题复现：主动让一帧抛出错误后，1.2 秒内恢复绘制并保留本地记录；模拟画布丢失/恢复事件后撤下恢复提示；主动让 React 子树抛错后看到重载承接页。**模拟事件不是让 GPU 真正崩溃，也不证明用户那次卡死已经根治。** 该最终浏览器流程没有额外的未处理脚本异常，实际采集流程操作错误和位置校正为 0。

## 局域网 HTTP 采集异常根因（2026-10-21，取得原设备堆栈后）

用户提供的记录明确显示：`NetworkManager.gameAction` 调用 `crypto.randomUUID()` 抛出 TypeError，经采集完成时的 `IsometricEngine.update` 进入统一画面异常处理。这里的“画面发生错误”包括更新阶段异常，不能由提示文字推断为绘图/GPU 故障。

在本机实际局域网 HTTP 地址 `http://172.16.1.65:39120`（独立验证库）确认 `isSecureContext === false`、`crypto.randomUUID` 缺失、`crypto.getRandomValues` 存在。修改前正常走到树旁采集，复现同样的堆栈，而且没有发出游戏操作包。原始证据在 `data/lan-uuid-before.json`。此前使用 localhost 的测试环境属于可受信任的本地来源，未覆盖这一差异。

依据 [MDN randomUUID](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/randomUUID)，该接口限安全上下文；[getRandomValues](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/getRandomValues) 可在非安全上下文使用。

最小修复仅涉及 `NetworkManager.gameAction`：存在原生接口时继续使用；缺失时用 `getRandomValues` 生成 16 字节、设置 UUID v4 的版本和变体位，生成相同格式的请求编号。操作参数、服务器幂等规则、认证身份与服务端 UUID 生成均不变，不引入依赖，不以时间戳或普通随机数代替随机源。

新增回归测试先在旧实现上因相同 TypeError 失败，修复后通过，覆盖原生分支、缺失接口时的格式与实际发包，以及同一毫秒两个管理器生成 512 个不重复且格式合法的请求编号。最终完整测试 22 个文件、239 项通过，类型检查和构建成功；构建的已有包体积与配置迁移提示仍存在。

只读检查用户正在使用的 `http://172.16.1.65:3000/src/game/NetworkManager.ts`，已返回带能力检查及兼容分支的代码（HTTP 200）；该修改是客户端逻辑，刷新页面即可加载，无需为此强停正在使用的服务。

修复后继续使用真实局域网 HTTP、保持 `randomUUID` 自然缺失，没有注入接口或修改安全上下文：长按砍树得到木材 3、长按采石得到石料 3，节点均归零，无业务错误和画面诊断；另外用全新账号单独搜索并取走木料箱，木材增加 3、节点归零，搜索与取物请求编号格式正确且互不重复，无业务错误或画面诊断。箱子结果在 `data/lan-uuid-box-after.json`，执行脚本为 `data/validate-lan-uuid.cjs`、`data/validate-lan-box.cjs`。

测试脚本的初次箱子验收提前交互时角色尚未停稳，另一次轮询又重复点击取物，均修正验证脚本；不把脚本错误当成需要改动游戏逻辑的证据。最终箱子测试为停稳后开始搜索、只点击一次取物。上述流程验证了本次明确堆栈对应的故障，不代表此前所有内存、GPU 或未知整页卡死问题已经解决。独立测试服务及测试浏览器关闭，用户 3000 端口服务未被停止，真实存档未被替换。
