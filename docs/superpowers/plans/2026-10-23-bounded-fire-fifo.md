**Goal:** Accept measured legitimate compressed input while preserving the actual authoritative firing cadence, fresh validation, atomic ammunition/replay commits and a strict finite input/latency budget. This replaces the implementation's one-slot assumption; it does not redefine the weapon rate or count a wider buffer as a performance cure.

**Evidence:** HEADd0260b3 retained zero errors for780 two-native rounds but final eight-connection gate failed2/1 refusals. Paired samples had current/previous outbound gaps121–134ms, receipts65–112ms apart, and another pending shot with estimated3–49ms planned wait left. Query work fell41% and full refreshes were phased, yet these occupied-slot refusals remained. Sustained input is slower than the weapon's120ms interval; a temporary receive burst can still exceed one slot.

**Alternatives:** Keep one slot and only reduce synchronous work (already insufficient in measured runs); increase instantaneous timing grace (changes damage timing and is rejected); bounded FIFO with unchanged actual execution pacing (selected). No client timestamps or response-paced client throttling. Do not hide errors or claim arbitrary jitter can never overflow a finite queue.

## Contract

- At most2 pending fire inputs per connection and one head timer. Each entry's absolute monotonic expiry is admission time+2 authoritative weapon intervals:240ms for rifle/default120ms weapons,560ms for crude_gun280ms. Cancellation/expiry never spends ammunition or marks handled. Timer blockage may delay feedback, but resumed processing must discard entries older than their age budget.
- The head deadline follows server readiness; a second deadline is at least one weapon interval after its predecessor. Refuse admission if the planned deadline exceeds that entry's expiry. After a head callback completes (including validation, commit, reply and broadcasts), rebase the successor no earlier than that completion+its interval; discard it if its fixed admission-age budget can no longer fit. This conservative queued-successor spacing includes processing cost and never replays overdue queued damage in one instant. The existing immediate-path jitter/debt semantics remain unchanged; this is not a claim that every original immediate damage event has strict wall-clock spacing. Equality at expiry is allowed; only now>expiry or planned due>expiry cancels.
- Normal ready input with an empty queue uses the existing action path and existing20ms cooldown-debt validator. Buffered shots wait their full authoritative readiness window. GameWorld exposes current readiness/interval/context for valid unhandled fire, without modifying perform/cooldown or trusting client fields. Over-budget readiness takes the normal rejection path; queued inputs cannot overtake their predecessors.
- Coalesce either pending request ID across all action types. Committed replays remain immediate. A distinct new fire beyond capacity is explicitly refused. Invalid packets/ammo/weapon cases remain normal validation; no speculative resource reservation.
- All entries share the current map/weapon/respawn context. Context changes cancel every queued entry and give each live request cancellation feedback; close/replacement clears everything. At actual execution, recheck connection ownership/context and original target/range/LOS/friendliness/ammo/cooldown validation. Every success persists before acknowledgement; reply failure cannot undo it. Pending entries/timers are not persisted.
- Keep current refresh phases,2s shared checks,5s baseline/checkpoint targets, transport limits, client input cadence/graphics and legacy protocol behavior.
